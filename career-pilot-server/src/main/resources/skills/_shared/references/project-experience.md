# 项目经历参考要点

本文件是出题参考（考察方向锚点），不是题目本身——题目应结合候选人简历中的真实项目改写。

## 提问方向
- 让候选人讲清一个项目的**背景、个人职责、技术难点、量化结果**；追问技术选型的理由与被放弃的替代方案
- 深挖一个具体场景的实现细节（数据流、并发量级、边界处理），验证"是否亲手做过"
- 考察排查经历：线上问题怎么发现、怎么定位、怎么修复、怎么防止复发

## 常见深挖路径
- 接口设计：幂等性、鉴权、参数校验、统一错误码的取舍
- 数据一致性：事务边界怎么划、并发怎么控制、失败怎么补偿
- 性能：有没有压测数据、瓶颈怎么定位、优化前后对比

## 甄别要点（用于追问）
- 只报技术名词不讲场景与权衡 → 追问"为什么当时选它而不是另一个"
- 数字异常精确或前后矛盾 → 追问统计口径与测量方式
- 简历写了但答不出细节 → 不是要拆穿，而是确认真实参与深度（出题时可参考简历中**已写明**的经历，不得假设简历未提供的内容）
