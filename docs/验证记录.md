## 1. JWT 登录认证（2026-10-09）

### 验证对象

《API接口设计》第 3 节的认证与用户接口。实现位于 `career-pilot-server`：

- `security/` —— `JwtTokenProvider`、`JwtAuthenticationFilter`、`CurrentUser`
- `config/SecurityConfig` —— 无状态会话、CORS、统一 401/403 响应
- `controller/`、`service/`、`dto/`、`entity/`、`mapper/` —— 认证业务链路

### 验证环境

| 项 | 值 |
|---|---|
| 后端 | JDK 21，端口 8080，profile = local |
| 启动方式 | `java -jar target/career-pilot-server-0.0.1-SNAPSHOT.jar` |
| 数据库 | MySQL 8.0.46，库 `career_pilot` |

### 实测步骤与结果

**① 注册**

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","email":"test@example.com","password":"Test1234"}'
```

```json
{"code":0,"message":"success","data":{"avatar":null,"email":"test@example.com",
 "id":2,"nickname":"testuser","username":"testuser"},
 "timestamp":"2026-10-09T15:31:05.6689213"}
```

**② 登录**

```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"account":"testuser","password":"Test1234"}'
```

返回 `token`、`tokenType: "Bearer"`、`expiresIn: 7200` 与用户资料，结构符合《API接口设计》2 节。

**③ JWT 算法核验**

Token 头部解码为：

```json
{"alg":"HS256"}
```

与设计约定一致（《系统架构设计》7 节、《API接口设计》2 节均要求 HS256）。

> 首次实测时发现实际签发出的是 HS512 —— jjwt 的 `signWith(Key)` 会按键长自动选择算法，
> 64 字节密钥被选为 HS512。已改为显式 `signWith(key, Jwts.SIG.HS256)`。

**④ 带 Token 访问受保护接口**

```bash
curl http://localhost:8080/api/user/profile -H "Authorization: Bearer $TOKEN"
```

→ HTTP 200，返回当前用户资料。

**⑤ 不带 Token 访问**

→ HTTP 401，响应体：

```json
{"code":40100,"message":"未登录或登录已过期","data":null,"timestamp":"..."}
```

**⑥ 错误密码登录**

→ HTTP 401，`code: 40100`，提示"账号或密码错误"（**不区分**账号不存在与密码错误，避免账号枚举）。

### 结论

六项全部通过，认证闭环可用。测试数据（`testuser`）已在验证后清理。

### 遗留

- 服务端不实现 Token 撤销机制（按《API接口设计》3.5 的设计），退出登录由前端清除本地 Token 完成。
