# 智能求职辅助平台：系统架构设计

- 课题名称：基于SpringAI的智能体应用开发
- 业务名称：智能求职辅助平台
- 文档版本：V1.0
- 状态：开发基线（实现时如需调整，应同步更新本文档及相关文档）

## 1. 设计目标

本系统面向个人求职者，提供简历管理、岗位管理、简历与岗位匹配、AI 面试和求职智能体等功能。架构应满足本科毕业设计的可实现性、可维护性和可演示性。

设计原则：

1. 优先采用单体分层架构，不引入微服务。
2. 普通业务逻辑与大模型调用解耦。
3. AI 输出使用结构化对象校验后再保存。
4. 所有用户私有资源均执行当前用户归属校验。
5. 大模型 API Key 仅在后端配置，不下发到浏览器。
6. 第一版不依赖 Redis、向量数据库、RAG、多智能体或招聘网站爬虫。

## 2. 技术选型

| 层次 | 选型 | 用途 |
|---|---|---|
| 前端 | Vue 3、Vite、Vue Router、Pinia | 页面、路由和状态管理 |
| UI | Element Plus（建议） | 表单、表格、弹窗和报告展示 |
| HTTP | Axios | 请求封装、JWT 携带、错误处理 |
| 后端 | Java 17、Spring Boot 3 | REST API 与业务逻辑 |
| AI 集成 | 与当前 Spring Boot 版本兼容的 Spring AI 版本 | ChatClient、结构化输出、工具调用 |
| 模型 | DeepSeek API | 文本理解与生成 |
| 数据库 | MySQL 8.x | 用户和业务数据持久化 |
| ORM | MyBatis-Plus（建议）或 Spring Data JPA（二选一） | 数据访问 |
| 认证 | Spring Security + JWT | API 身份认证和授权 |
| 文件解析 | Apache Tika 或 PDFBox + Apache POI | PDF/DOCX 文本提取 |
| 构建 | Maven、npm | 项目构建 |
| 版本管理 | Git | 代码和文档管理 |

> 版本管理规则：不要随意混用不同 Spring AI 教程中的依赖版本。创建项目时，先根据 Spring Boot 版本选择兼容的 Spring AI BOM，并以实际依赖解析结果为准。

## 3. 总体架构

```text
Vue 3 浏览器端
  ├─ 登录/注册
  ├─ 简历管理
  ├─ 岗位管理
  ├─ 匹配报告
  ├─ AI 面试
  └─ 求职智能体
         │ HTTPS/HTTP + JSON
         ▼
Spring Boot REST API
  ├─ Controller：参数接收、响应封装
  ├─ Service：业务规则与事务
  ├─ Security：JWT 认证、资源归属校验
  ├─ AI Service：Prompt、模型调用、输出校验
  ├─ Agent：任务理解、工具调用、结果整合
  ├─ Tool：封装可供 Agent 调用的业务能力
  ├─ Mapper/Repository：数据库访问
  └─ File Service：上传、校验、解析和存储
         ├─ MySQL
         ├─ 本地文件存储
         └─ DeepSeek API（由 Spring AI 调用）
```

## 4. 后端分层职责

### 4.1 Controller 层

- 定义 REST API。
- 校验请求格式和必填字段。
- 调用 Service，不直接写 SQL 或直接调用模型。
- 返回统一响应结构。
- 不信任前端传来的 `userId`；用户身份从认证上下文获取。

### 4.2 Service 层

- 执行业务规则。
- 校验资源归属。
- 管理事务和状态。
- 协调 Mapper、文件服务和 AI 服务。
- 对 AI 调用异常、超时和解析失败进行处理。

### 4.3 AI Service 层

- 构建 Prompt。
- 调用 Spring AI 的 ChatClient。
- 将模型输出转换为 DTO/结构化对象。
- 校验分数范围、字段完整性和数组长度。
- 不直接信任模型生成的 ID、权限或数据库操作指令。

### 4.4 Agent 与 Tool 层

- Agent 负责接收用户任务、选择可用工具并整合工具结果。
- Tool 只提供有限、明确的业务能力。
- Tool 必须通过当前认证用户或显式传入且经过服务层校验的用户上下文限制访问范围。
- 不向模型开放任意 SQL、任意文件路径或任意网络访问能力。
- Tool Calling 是模型提出工具调用请求，后端执行工具后把结果交还模型；工具本身的授权与参数校验由后端负责。

## 5. 主要业务模块

| 模块 | 主要职责 |
|---|---|
| Auth | 注册、登录、JWT |
| User | 当前用户资料 |
| Resume | 简历上传、列表、详情、删除、文本提取 |
| Resume Analysis | 简历结构化分析与建议 |
| Job | 目标岗位 CRUD |
| Job Analysis | 岗位职责与技能要求提取 |
| Match | 匹配分析、差距和建议 |
| Interview | 面试会话、题目、回答评价 |
| Agent | 求职任务对话、工具调用、消息记录 |
| History | 查询历史分析记录 |

## 6. 核心业务链路

### 6.1 简历处理

```text
用户上传 PDF/DOCX
  → 校验扩展名、MIME、文件大小
  → 生成服务端文件名并保存
  → 提取文本
  → 检查文本非空且长度合理
  → 保存 resume 元数据与文本
  → 用户主动发起 AI 分析
  → Spring AI 调用 DeepSeek
  → 校验结构化输出
  → 保存 resume_analysis
```

建议初始限制单文件 10 MB；该数值是项目配置项，部署时可调整。扫描版 PDF 可能无法直接提取文本，第一版应提示用户上传可复制文本的 PDF，OCR 作为后续扩展。

### 6.2 岗位匹配

```text
用户选择简历和岗位
  → 校验两者均属于当前用户
  → 获取最新简历分析与岗位分析
  → 缺少分析结果时先生成或提示用户分析
  → MatchService 计算匹配结果
  → 保存 match_record
  → 返回匹配报告
```

建议评分由后端确定性规则计算，模型负责解释和提出建议。评分权重放入配置，不应让模型任意返回一个无法解释的分数。

### 6.3 Agent 工具调用

```text
用户请求
  → AgentController 校验身份与请求
  → JobAssistantAgent / ChatClient
  → 模型判断是否调用工具
  → 后端执行已注册 Tool
  → Tool 调用对应 Service
  → 工具结果返回模型
  → 模型生成最终答复
  → 保存会话消息与工具调用摘要
```

## 7. 安全设计

1. 密码使用 BCrypt 等成熟密码哈希算法存储。
2. JWT 使用高熵密钥，设置过期时间；密钥放环境变量，不写入仓库。
3. 用户资源查询必须带上 `user_id` 条件，例如 `WHERE id = ? AND user_id = ?`。
4. 文件名采用服务端生成的随机名称，不能直接将用户文件名拼接为磁盘路径。
5. 校验文件大小、扩展名和 MIME；禁止执行上传文件。
6. 对模型输入做长度限制，模型输出按 DTO 和业务规则校验。
7. 日志不记录密码、JWT、API Key 或完整敏感简历内容。
8. 删除简历时明确是否同步删除原文件和关联分析数据。
9. 对外部模型 API 设置合理超时和异常提示。
10. 对用户提交的简历内容视为不可信数据，Prompt 中明确它只是待分析材料，不是系统指令。

## 8. 异常处理约定

| 场景 | 处理方式 |
|---|---|
| 参数不合法 | 返回 400 |
| 未认证/Token 无效 | 返回 401 |
| 无权访问资源 | 返回 403，或按安全策略统一返回 404 |
| 资源不存在 | 返回 404 |
| 文件格式不支持 | 返回 400 |
| 文件过大 | 返回 413 |
| AI API 超时/不可用 | 返回 502 或业务错误码，允许用户重试 |
| AI 输出无法解析 | 不保存无效结果，记录脱敏错误并提示重试 |
| 未预期异常 | 返回 500，响应中不泄露堆栈 |

## 9. 部署结构

开发环境建议：

- 前端：Vite 开发服务器。
- 后端：Spring Boot 本地运行。
- 数据库：本机 MySQL。
- 文件：项目运行目录之外的本地目录。
- 模型：调用 DeepSeek 远程 API。

生产/演示部署时，前端可构建为静态文件并由 Nginx 或后端静态服务提供。数据库密码、JWT 密钥和 DeepSeek API Key 通过环境变量或本地未提交的配置文件注入。

## 10. 第一版验收标准

- Vue 前端可以访问 Spring Boot API。
- 用户注册、登录和 JWT 认证可用。
- 用户只能查看和操作自己的简历、岗位及分析记录。
- PDF/DOCX 上传与文本提取成功。
- DeepSeek 简历分析和岗位分析成功，结果以结构化格式保存。
- 匹配报告能展示分数、匹配项、差距项和建议。
- Agent 至少能调用简历分析、岗位分析或匹配中的两个业务 Tool。
- AI 面试能生成题目并评价文本回答。
- API Key 不暴露给前端，异常时不返回敏感信息。
